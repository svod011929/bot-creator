# Источники ОП креатора

Пользователь уточнил: нужны задания, которые TGrass/PiarFlow выдают по ключу его источника, а не фильтр собственных рекламных кампаний. Обычная разработка/review делегирована; это не утверждение о личном прочтении данного файла.

## Решение и варианты
1. Рекомендуется: два admin-only источника, общий безопасный store, прежние заявки/factory-first и fallback. Минимальный работающий срез.
2. Только инструкции для env не подходят: нет управления из креатора.
3. Локальная рекламная биржа/фильтр campaigns не соответствуют уточнённому запросу и не реализуются.

## UI и безопасность
`/admin` → `📡 Источники ОП` → `TGrass` / `PiarFlow`. Видны происхождение ключа (сервер/сохранённый/старый автокэш/не задан/ошибка чтения), наличие factory credential и пояснение «Ключ записан; работа у провайдера не проверена». Сам ключ, длина, хвост, raw ошибки отсутствуют.
`🔑 Задать / заменить ключ` → предупреждение: «Telegram-чат не является хранилищем секретов и не имеет сквозного шифрования. Сообщение попробуем удалить, но гарантировать удаление нельзя. Введите API key источника, не токен Telegram-бота». Введённое сообщение удаляется best effort до проверки. Никакого echo. Кандидат хранится только в ограниченном RAM (128, TTL10мин), не в FSM/DB. `💾 Сохранить` с одноразовым nonce подтверждает запись; `🗑 Удалить сохранённый ключ` имеет отдельное подтверждение. Cancel/back не сохраняют.
Только текущий admin в своём private chat. Нельзя прерывать чужой активный мастер. Confirmation связан с текущими FSM/provider/nonce и revision; повторные/просроченные/пересланные/поддельные кнопки не меняют ничего. `/start`, `/cancel`, главное меню и `/admin` сбрасывают кандидата. Неподдерживаемый ввод отклоняется без цитирования.

## Хранение/precedence/rotation
Приоритет: непустой env HUB_API_KEY → ручной `data/sponsor_sources/{provider}.json` → прежний `data/{provider}_hub.json` → прежняя автоматическая регистрация хаба при наличии factory credential. При env ключе UI запрещает изменения, явно указывает серверный приоритет. Ручной файл версия1, api_key и случайная revision. Подкаталог0700, файлы0600, bounded read8KiB, symlinks не допускаются; lock+optimistic revision предотвращают конкурирующие сохранения. Temp+fsync+atomic replace; ошибка до commit сохраняет прежний ключ, не попадает в ответ/лог. Повреждённый существующий файл блокирует fallback до явного исправления, а не запускает случайную регистрацию.
Удаление касается только ручного ключа; экран предупреждает о возврате к прежнему автокэшу/авторегистрации при наличии factory, не обещает отключить уже работающих child. Env и старые cache-файлы никогда не переписываются UI. Развёртывание не создаёт/меняет secret-файлы.
Изменения применяются при следующих одобрениях pending и повторном включении disabled relay. Уже approved записи и factory-ключи не ротируются; не обещать горячую массовую замену. Снимки ключей действующих child сохраняются при рестарте даже без factory credential. Для смены старого relay требуется обычное явное отключение/повторное одобрение; UI настроек сам этого не делает.

## Runtime
Factory credential отсутствует → пропустить factory, взять явно заданный/сохранённый источник без внешнего запроса. При ошибке factory → прежний fallback. Нет доступного ключа и нет возможности авторегистрации → остаётся pending/disabled, без apply_changes/награды. Известные provider-ошибки отображаются только типизированным безопасным текстом. Новые UI-сохранение/статус не вызывают API, restart, sync_all или финансовые операции. Сервисы могут создаваться после сохранения; существующие периодические sync_loop запускаются runtime lifecycle, ставки/курсор/credit методы не меняются. Startup не проверяет баланс PiarFlow для утверждения live-health.

## Приёмка и границы
Тесты temp DB/fake Telegram/HTTP: precedence, совместимость, отсутствие factory, factory failure, обе ошибки, save failure, invalid/symlink/oversize, concurrent save, rotation/replay/expiry/current admin/private/FSM, escaping/Telegram limits, snapshot DB/settings и отсутствие secret в ответах/логах/FSM. Полная регрессия, Ruff/compile/offline dry-run, AST финансовых функций. Нет миграции DB, новых провайдеров, live регистрации/проверок/ключей, сумм/платежей/наград/гейтов, C4. A1 и provider E2E не проверены. API источники: https://piarflow.com/api-docs и https://piarflow.com/llms.txt; исключительность рекламодателей не обещается.

Self-review: приоритет един; удаление не равно disable; runtime активация без factory предусмотрена; потеря/порча не ноль/не live; ключ не хранится FSM; нет несогласованных функций или обещания массового обновления. Внешние проверки остаются отдельным разрешением.
